# Investigation lane handoff

Implemented the nine-action broker, sanitized planner projection, structured Astra CLI adapter, deterministic greedy/coverage policies, and independent offline comparison runner. No live model request, cloud inspection, or demonstration was run by this lane.

Exports are in `src/server/planner/index.ts` and `src/server/broker/index.ts`. `createBroker(session, collector)` validates and atomically reserves the four-credit ledger, binds retries to their complete parsed request, validates returned source/action/subject/predicate/run/revision scope, and preserves cost on dispatched failure. After revision zero only a fresh `OPERATOR_VERIFICATION` CLI check is allowed. Original receipt objects cannot be changed by retry callers.

`buildPlannerView(session, assessments, now?)` and the final serializer independently rebuild a bounded allowlisted request. Free-text labels, observation/source IDs, evaluator prose, page evidence, previous model rationale, and provider error text do not enter the request. Facts receive local opaque IDs. `CliAstraPlanner({executable?,model?,timeoutMs?,onTrace?})` uses the app-bundled CLI by default, isolated temporary working directories, disabled shell/apps/multi-agent/web, strict output, bounded bytes, timeout process-group termination and cleanup. The child receives only an environment allowlist, not arbitrary provider token variables. Logs contain hash, byte counts, elapsed time and outcome only.

The adapter detects emitted tool/command/file events as transport failure. Its disabled-tool flags and global ambient Codex skill context still require explicit live acceptance against the installed CLI; offline subprocess tests do not prove an external CLI's complete effective context. Host CLI authentication remains owned by the CLI and is never extracted or copied by the app.

`runComparison({planners,factory,variants?,maxSteps?})` requires independent sessions/ledgers with equivalent semantic starting-state hashes for each variant. Each factory returns `{session,collector,evaluate,applyChange}`. The runner owns each broker and paid fresh verification. Frozen policy versions, first-choice acceptable sets, attainable outcomes and metric definitions are embedded in the report. Later decisions are also audited against missing prerequisites, source validity and the remaining budget; changing wording or action alone earns no score. Failed model attempts remain recorded; there are no rerolls. Unsupported factual assertions in rationale are explicitly `null` / `NOT_AUTOMATED`, requiring semantic review rather than a false zero. Only actual configured model runs may receive `mode: LIVE`.

Validation: Node 24 typecheck and focused offline tests cover concurrent exact/conflicting retries, independent reservation races, no overspend, cost-preserving failures, malformed scope, broad collection fact smuggling, invalid provenance and carry references, in-flight revision changes, fresh verification origin, serialized outgoing marker exclusion, deterministic adaptation, malformed model output, output limits/symlinks, missing CLI, timeout termination, ignored-tool-flag events, environment filtering, comparison state isolation and retained failed attempts.
