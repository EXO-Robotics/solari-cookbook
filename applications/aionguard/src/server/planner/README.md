# Astra decision transport

AionGuard invokes the configured Codex executable with the requested model (default `gpt-6-astra`). It uses the CLI's existing authentication; the application does not read, copy, or log authentication tokens. The installed executable used for September 10 integration qualification is `/Applications/Codex.app/Contents/Resources/codex`, version `0.153.4`.

Each decision uses an ephemeral process in a fresh temporary directory. The application reconstructs the request from allowlisted synthetic facts and canonical action definitions. Inspected URLs, page text, screenshots, provider errors, model rationale from earlier decisions, and private collector truth are excluded from that request.

The invocation ignores user configuration, suppresses project-document loading, disables memory use/generation and host skill discovery, and disables hooks, plugins, apps, shell, browser/computer tools, subagents, image tools, goals, sleeps, and workspace dependency tools. The child inherits only a small environment allowlist needed for CLI operation and authentication. These are invocation-local settings; personal Codex configuration is unchanged. See the official [configuration reference](https://learn.chatgpt.com/docs/config-file/config-reference) for the memory and feature settings. `skip_host_skill_discovery` is an installed-CLI feature and is under development; compatibility must be rechecked when changing the CLI.

`astra-cli-2` uses a strict object containing a `decision` union. INVESTIGATE requires its catalog action, target, hypothesis IDs, and short rationale. STOP contains only its type and rationale. The old flat nullable schema permitted STOP fields that the application decoder rejected; the new schema and decoder agree. Model output is never converted into an observation or authoritative assessment.

The JSONL transport must contain one started and completed turn. Only agent-message and reasoning item types are accepted; their prose is not used by the event guard or copied to diagnostics. Errors, unknown events, tool events, incomplete turns, malformed decisions, excessive output, and timeout all fail closed. The event guard is a detector after emission, not a substitute for disabling capabilities before launch or a security boundary against a compromised CLI.

`npm run compare -- --live-astra` records immutable independent comparison reports and companion `.astra-traces.json` files under ignored `runtime-data/comparisons/`. Traces contain the configured model, request SHA-256 and byte count, response byte count, latency, and outcome. They contain no prompt text, model prose, stderr, authentication data, or local paths. Failed attempts remain available. Console output distinguishes attempted from completed Astra runs. Comparison evidence cannot enter the active case ledger.

Qualification establishes application request exclusion, functioning configured CLI restrictions, structured decisions, lifecycle checks, and observed outcomes. It does not provide exhaustive introspection or attestation of the CLI's private upstream model request. The CLI's `debug prompt-input` command does not expose `exec`'s `--ignore-user-config` option, so it is not an equivalent audit of this invocation. No general model-superiority claim follows from the small synthetic comparison.

The immutable report above predates this wording fix; it remains unchanged, and its automatic unsupported-assertion metric remains unmeasured. Subsequent integrated acceptance must identify its own source state and results.
