# Registered Safari navigation

These are extension resources and deterministic source/package generators for a development-signed Safari extension. AionGuard is manually enabled and paired on the intended Mac. A recorded normal-click sequence from a controlled email reached the holding page and a real Vercel inspection; the screenshot, suspicious classification, and sandbox cleanup were observed. This bounded demonstration is separate from comprehensive endpoint-interception acceptance. The receipt still reports `endpointInterceptionVerified: false` because independently attributed local request suppression and the broader navigation matrix are unfinished.

## Installation and permissions

1. Configure the controller and inspector for the same owned, registered HTTPS target; follow the [controller setup](../../docs/setup.md) and [signed app build instructions](recovery/README.md). The demo target is `https://mfrey18.github.io/AionPhish/`.
2. Build the containing app with an existing Apple Development identity. Install and physically enable AionGuard in Safari Settings → Extensions in the intended profile. This is a development package, not an App Store installation.
3. Grant access to the registered host and loopback controller. Safari's host permission covers `mfrey18.github.io`; AionGuard's rules are narrower and exclude sibling projects. The demo's one-day grant is temporary and may need renewal.
4. Pair the extension from the local `entry-token` file. Connect the containing recovery app to the separate `recovery-token` file through its file picker, and grant Input Monitoring to that app when required. Never enter the full controller token into extension settings.
5. Start the controller and helper with protection off. Check recovery readiness and a matching positive Safari rules-removal acknowledgment. Verify physical `0000` recovery in an ordinary input window during a short test lease before attempting a protected click. A new arm is always explicit.

Safari previously refused activation with its click-interference warning. The user subsequently enabled the extension manually. Automated activation is not a supported setup step, and this project does not bypass Safari's activation protection.

## Recorded behavior and recovery limits

The demonstration arms a short lease, clicks the registered link, shows the holding page and a captured Vercel inspection image, then explicitly releases protection and opens the controlled destination for comparison. The image is a captured inspection result, not a live remote browser stream. The native recording overlay reports scoped application state; it does not indicate macOS Lockdown Mode or a compromised operating system.

Physical `0000` from TextEdit and a real 20-second lease expiry separately removed installed rules with matching native acknowledgments. Automated zero-key input failed to trigger release in the recorded retry, so explicit disarm was used and acknowledged. Secure Input can prevent key delivery; missing recovery readiness triggers release. Do not rely on an unconditional keyboard shortcut guarantee. If browser rule removal fails, disable the extension or fully quit Safari. See [recovery setup and verification boundaries](recovery/README.md).

Some recording attempts released early when recovery readiness was lost; another first click opened a blank tab before a retry reached inspection. These remain reliability issues. The successful retry does not qualify suspension, restart, modified clicks, all redirects, or independent local request suppression.

## Rule and handoff design

`build.ts` requires the same registered HTTPS target used by the controller: an exact path URL or the legacy dedicated origin. It produces a Manifest V3 package that is disarmed by default. During an explicit, time-limited controller lease with a healthy recovery helper, session-only rules redirect the exact registered URL for main-frame requests. Other request types are blocked within its registered directory or resource; the legacy dedicated-origin input retains the original whole-origin block. For `https://mfrey18.github.io/AionPhish/`, the block covers `/AionPhish`, `/AionPhish/`, and descendants, while sibling projects remain outside the rules. Safari host permission remains origin-level. There are no content scripts, arbitrary URL commands, content embeddings, or local destination fetches. Emergency controls and the `0000` detector run only in extension-owned pages; a separate passive Mac helper provides ordinary desktop keyboard recovery. See [recovery setup and limits](recovery/README.md).

For another installation, generate the resources into a separate output directory using `npx tsx src/extension/build.ts <registered-origin-or-url> <output-directory>`. The generated directory can then be supplied to Apple's Safari web extension packaging/conversion tool. Packaging, signing, enabling the selected profile, and host permission grants are separate device work. Do not point the generator at an unrelated browsing origin.

The holding page sends only the registered fixture ID and a per-navigation idempotency ID. Reloads retry that same ID; a new navigation gets a new ID. The background page accepts messages only from this extension's exact holding page and attaches `AIONGUARD_ENTRY_TOKEN`, stored in extension-only settings. This token authorizes the narrow `/api/entry` command. It must be different from the full controller token. The controller must select a previously operator-authorized READY attempt; a missing authorization leaves the navigation held. Neither the extension nor the entry endpoint grants organizational-change authorization.

The holding document is a web-accessible redirect destination. A direct visit can therefore trigger the same bounded, preauthorized entry command. Rendering that page or receiving its message establishes a reported extension handoff, **not independent proof that Safari intercepted a destination request**. Per-tab message origin checks prevent arbitrary payload configuration; they cannot turn a directly opened holding page into interception evidence.

The controller now also requires an armed protection lease before accepting entry. Emergency disarm, expired leases, and recovery failures stop test protection and require a new explicit arm. Browser API failure must be resolved by disabling the extension or quitting Safari; no system-wide restriction is installed.

During recovery, legacy static-rule cleanup queries enabled rulesets and disables `registered_fixture` only when present. The query and update are serialized across concurrent disarms, avoiding Safari's error when disabling an already disabled ruleset. Dynamic and session rules are removed independently. A failed query or removal produces a failed acknowledgment and does not prevent a later retry.

Installed Safari initially rejected a generated regular expression; that failed attempt remains recorded. The equivalent supported expression passed `isRegexSupported`, 38 focused software tests, and the later rule-installation check. The background now retains its production native port for the connection's lifetime and clears it on disconnect. This corrected the missing acknowledgment in the repeated bounded device test. The connection survived a debugger-requested garbage collection with Web Inspector attached; Safari background suspension and restart coverage remain separate gates. Final source checks passed 263 tests across 14 files, TypeScript, production build, formatting, and diff checks.

Before claiming protection, verify the actual installed Safari version and profile with normal clicks, modified/new-tab clicks, browser closed/open routing, redirects into the registered URL, reload/back/forward behavior, and applicable subframe/prefetch/resource requests. Measure local request suppression independently, with origin attribution rather than destination logs alone. Missing host access, private browsing/profile differences, API support, extension reloads, and concurrent navigation must be included. This device matrix is a required engineering acceptance gate; source tests do not establish Safari coverage.

The Safari scope is one registered HTTPS URL and its bounded directory/resource (or the legacy dedicated origin). Other sites, mail-provider scanning, the email body, and the physical Mac are outside this implementation's interception claim.
